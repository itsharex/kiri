## English

- macOS video-to-GIF conversion now shows measured frame progress, followed by finalizing and saving stages. Opening the library during conversion restores the active progress display.
- Conversion failures keep their specific reason visible with Retry and Close actions. Immediate command errors and repeated failures are no longer silently discarded; decoder errors include the failing frame and time.
- macOS encodes GIF frames as they are decoded instead of retaining the whole animation in memory. A generated 60-second, 320×320 sample used about 33 MiB peak RSS with the optimized streaming encoder, compared with 807 MiB with the previous encoder. This is a sample measurement, not a speed improvement or a confirmed diagnosis of every conversion failure.
- GitHub's issue chooser now also accepts questions.

Contributors to this release: @yuxino.

macOS and installed Windows builds use the signed, user-initiated updater. Windows Portable updates by replacing its ZIP. On Linux, install with `sudo apt install ./kiri_1.6.11_amd64.deb`; updates replace the `.deb`. macOS retains Kiri's stable local signing identity and is not Apple-notarized; if blocked, approve it through **System Settings → Privacy & Security → Open Anyway**. Windows packages are not Authenticode-signed.

Verification includes a successful native macOS conversion with visible progress, a damaged-video failure and repeated retry, decoded GIF frame timing and orientation, and automated frontend and Rust checks. Windows and Linux package checks are automated; physical devices, hardware recording and GNOME Wayland were not exercised for this change. The original private failing video was unavailable, so its exact failure cause remains unconfirmed. Windows and Linux conversion display remains indeterminate while encoding.

Full changelog: [v1.6.10 → v1.6.11](https://github.com/yuxino/kiri/compare/v1.6.10...v1.6.11).

## 中文

- macOS 视频转 GIF 现在显示根据已编码帧数计算的进度，并在随后显示完成编码和保存阶段。转换过程中打开素材库，也能恢复当前进度。
- 转换失败会保留具体原因，并提供「重试」和「关闭」。立即返回的命令错误和重复失败不再被丢弃；解码错误会显示失败的帧数和时间位置。
- macOS 改为解码一帧、编码一帧，不再将整个动画的帧保留在内存中。使用生成的 60 秒、320×320 测试视频，优化后的逐帧编码峰值 RSS 约为 33 MiB，原编码方式约为 807 MiB。这是单个样本的测量结果，不代表速度提升，也不能确认所有转换失败的原因。
- GitHub 的 issue 选择页现在也接受使用问题。

本次版本贡献者：@yuxino。

macOS 和 Windows 安装版使用用户主动触发的签名更新。Windows 绿色版通过替换 ZIP 更新。Linux 请用 `sudo apt install ./kiri_1.6.11_amd64.deb` 安装，并通过替换 `.deb` 更新。macOS 沿用 Kiri 的稳定本地签名身份，尚未经过 Apple 公证；若被拦截，可在「**系统设置 → 隐私与安全性 → 仍要打开**」中批准。Windows 包尚未使用 Authenticode 签名。

验证包括 macOS 原生转换成功及可见进度、损坏视频失败及连续重试、GIF 解码后的帧时间与方向，以及前端和 Rust 自动检查。Windows 和 Linux 安装包通过自动检查；本次未验收物理设备、硬件录制和 GNOME Wayland。未取得原先转换失败的私有视频，因此尚未确认那次失败的具体原因。Windows 和 Linux 在编码期间仍显示不确定进度。

完整变更：[v1.6.10 → v1.6.11](https://github.com/yuxino/kiri/compare/v1.6.10...v1.6.11)。
